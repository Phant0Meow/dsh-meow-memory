# 设计说明

为什么 meow-memory 这样设计。这里记录的是取舍与踩过的坑，不是功能清单。

---

## 1. 为什么静态手册放 system prompt，而动态内容进第一条用户消息

| 内容 | 去哪 | 为什么 |
|---|---|---|
| 静态记忆手册（数据总览 + 工具用法 + 写作准则） | **system prompt** 的固定 section | 文本恒定，因此**不会破坏 LLM provider 的 KV/上下文缓存** |
| 动态内容（soul/user 全量、设计原则、记忆导引） | **第一条用户消息的前缀** | 内容随工作区变化，放 system prompt 会让缓存每次失效 |

静态 section 名为 `meow-memory:guide`，**order 130，紧随各 `tool:*` 说明之后**，注册一次、文本恒定。

记忆本身作为**独立 plugin snapshot 消息**放在真实 user 消息之前，**不改写用户 prompt**。

---

## 2. 为什么首轮不跑关键词命中

首轮只注入长期记忆快照，**命中从第二轮起**。原因：第一条用户消息与插件通知消息可能同批到达（如 approval policy 变更通知），若在首轮就做命中，命中内容会插到通知消息那一轮，而不是真实用户消息那一轮。

因此设计为：**快照紧贴插入到真实用户消息之前，命中绝不提前**。

---

## 3. 为什么命中基于条目关键词，而不是全文

全文匹配噪音大——一段记忆里出现某个词，往往不代表这条记忆与当前话题相关。

所以：**命中基于条目关键词**（LLM 提取或自动 bigram）。

打分公式：

```
交集分 × idf × 覆盖率 × 艾宾浩斯衰减（按记忆时间戳）× importance 权重 × title 加成
```

`importance` 与 `title` 都参与打分，所以写入时把它们填准是值得的。

---

## 4. 为什么"已见"要按会话记录

已见记忆（`injected` + `searched`）按会话记录在 `sessions/<id>.json`：

- **注入绝不重复**
- `memory_search` 前 5 条按相关度无脑取（**不排除已见/本 session 建立的记忆**），其余从排名后续绕开已见补齐
- 收到会话压缩信号（`compaction/*`）时**释放已见记录**，允许压缩后被再次命中提取

前 5 条刻意不排除已见：如果一开始就排除，最相关的那几条永远取不到，检索会"越搜越偏"。

---

## 5. 为什么压缩后要重注入

会话被压缩（手动 `/compact` 或 token 压力自动触发）后，下一个用户消息轮自动重新注入：

- 长期记忆快照
- 本会话此前用 `memory_project` 查阅过的项目全景
- 本会话自己写入/更新过的记忆原文

（均按最新数据重新整理）

**压缩甩掉的"记性"一个回合就补回来，AI 不会因为压缩突然失忆。** 查阅过的项目按 `memory_project` 的调用留痕记录（`markProjectQueried`），全局标记不记（全局层走快照）。

---

## 6. 为什么按窗口 dream，而不是夜间窗口

原设计是夜间窗口。改成**按窗口**：窗口空闲 ≥ `idleMinutes`（默认 3 小时）即进入允许触发状态，**每个最后发言晚于上次 dream 的窗口由自己的主 agent 整理**。

好处：整理用的是**该窗口自己的完整会话上下文**，范围=本窗口建立 + 提取过的记忆。

分三轮：

| 轮 | 内容 |
|---|---|
| 1 | 原子记忆 project / fact / lesson / rules / soul / user |
| 2 | topic 记忆 |
| 3 | 项目总结（本窗口涉及具体项目时追加：调 `memory_project` 复查并精简成新的项目长期记忆，被取代的旧条目归档） |

---

## 7. 为什么有峰时抑制

`suppressWindows` 默认 09:00–12:00、14:00–18:00，是 **API 峰谷电价的峰时**——峰时调用更贵。及各自开始前 `suppressLeadMinutes`（默认 15）分钟内也不触发。

峰时结束后下一个检查周期自动触发；**进行中的 dream 不打断**。

`timeZone` 默认 `Asia/Shanghai`：用户机器时钟为美区时间，抑制时段必须按固定时区计算，否则峰时判断整个错位。

---

## 8. 为什么 `rules` 要防 churn

长期稳定的 `rules` 反复重审会变成"没话找话"式更新。`dream.rulesReviewDays` 默认 2 天：**`updated_at` 距今超该天数的稳定准则不进 dream 第 1 轮清单**；`0` = 不过滤。

---

## 9. 为什么"恢复默认"要区分出厂默认与 patch 基线

设置页原来的「恢复默认」只做"删掉 user 层字段、显示回落 base"，而 base = 出厂默认 + patch 基线（`cordis.patch.yml`），于是 **patch 里手编的非默认值会被当成"默认"还给用户**——实测踩到过（patch 写死的模型成了「反思/梦境换模型」的恢复默认结果）。

现在语义统一为：**恢复默认 = 回到插件出厂默认**。出厂默认值是单一来源（`src/defaults.ts`），host 与 client 共用。

---

## 10. 为什么不用独立 fork 子代理执行整理

独立 fork 子代理执行方式已于 **v0.24 移除**，不再提供"独立执行"开关。

现在反思轮和 dream 各组**始终在主窗口执行（steer）**——prompt、模型回应、工具调用落在主会话 log（折叠 UI 负责视觉收纳）。

换模型改用 `delegate.model`：反思/梦境轮发起的每个 LLM 请求经 dsh 的 `agent/request` waterfall 覆盖 provider/model，轮次结束自动换回主模型。实现是**无状态**的——按"当前 turn 是否携带反思/梦境指令标记"逐请求判定，用户中止、崩溃、热重载都不会留下"卡在换模型"的脏状态。

---

## 11. 为什么 dream 要防重复

四道机制：

| 机制 | 作用 |
|---|---|
| check 门（DB 原子 60s 检查节流） | 频次节流 |
| start 幂等抢占（`dream_pending`） | 防并发重复启动 |
| 中断自愈（未收尾的 dream 自动补收尾） | 半途中断也能收尾 |
| 孤儿收尾（跨实例/热重载后 turn 结束也能收尾） | 跨实例边界 |

另外：**插件注入轮的事件不刷新窗口活跃度——已 dream 的窗口不会反复被 dream。**

---

## 12. 为什么会话列表图标只追加/只移除自有节点

图标放进 dsh 会话行的状态槽位、状态点左侧：**只追加/只移除自有节点，不改写 React 拥有的子节点**。

原因：整槽替换会令 React 虚拟 DOM 失同步，commit 抛 `removeChild NotFoundError` 把侧边栏整树卸载。

行定位也**零 dsh 改动**：读 React 18 fiber（`__reactFiber$` 内部属性）拿会话行渲染 key = session id，**不依赖标题匹配**。

数据走全页共享的 **60s 轮询 diff**（v0.23.0 连接池修复，替代原 SSE 长连接）：`/meow-memory/dreamed-sessions` 与 `/meow-memory/skip-dreams` 各一次 GET；dream 开始推 `state:'dreaming'`、完成推 `state:'dreamed'`、有新活动推 `state:'active'`、跳过翻转推 `state:'skip'/'unskip'`；client 挂载时全量对账一次。

---

## 13. 为什么全局标记要随语言走

全局标记取自当前语言包 `labels.md` 的 `project.global`（中文包为「全局」，英文包为 `"global"`）。

**必须随语言走**——否则英文包里模型写的 `"global"` 会被当成一个叫 global 的项目：全局 rules 不再注入、项目列表里凭空多出一个项目。

取不到时（实例覆盖层的 `labels.md` 是老版本、缺键）回退真值：全局判定是检索热路径的语义，不能因为一个文案文件过期就 throw 掉整条注入链路。

---

## 14. 为什么零运行时依赖

`node:sqlite`（Node ≥22.13 默认可用；22.5–22.12 需 `--experimental-sqlite`）+ 自包含 esbuild 产物（`lib/index.js`）。**无原生模块。**

## 15. 为什么外部记忆库要设信任门（#64）

记忆库住在工作区里是产品核心设计（工作区带着记忆走），推论就是**任何人都能预置一个 `.dsh-meow`**。恶意仓库带一个造好的 `memory.db`（或 `PROJECT.md`，会被 autoMigrate 导入），受害者打开后首轮注入把内容装进「===== 长期记忆 ===== / 关于user」这个**全插件信任级别最高**的框里——攻击者文字被洗成「用户亲口说过的话」，且零交互（首条消息自动发生）、零提示（预置库非 isFresh，首建提示不触发）。宿主对 AGENTS.md 一类项目文件同样不设门，但那些内容模型知道是第三方项目文件；本通道的伪装级别更高，且是我们自己造的、关得掉。

**判据：机器本地注册表，一个来源就够。** `<全局目录>/trusted-workspaces/<归一路径哈希>.json`——放在工作区之外，仓库作者碰不到、不可伪造。工作区内部任何标记（seen 文件、db 内字段）都可随恶意库一起预置，一律不能用。

**登记时机三选一，覆盖全部正常流：**

1. **创建即登记**（getDb 发现 memory.db 不存在 → 本插件即将创建空库）：但要求当时 `.dsh-meow` 目录为空/不存在——只预置 `PROJECT.md` 不带 db 的攻击会借「创建即信任」+autoMigrate 溜进来，目录非空（排除集只认 memory.db*/dream-debug.log 这类运行残留）则不登记；
2. **升级播种**（apply 时读 `window-index.json`，把其中每个工作区登记为信任）：该文件同样在全局目录、不可伪造，且语义精确——「升级前本机实际打开过」= 信任纪元内的库，老用户零摩擦；
3. **`/meow-trust` 命令**（人工确认）：换机 / 恢复备份 / 自己拷目录的唯一交互点，写注册表即刻生效（各门控是活检查，无需重启）。

**未信任 = 读写整理全停**（与 disabledWorkspaces 同短路位：不注入、不命中、不 dream、不反思、工具全拒、不迁移 PROJECT.md），首轮插一次性说明（记账同样在注册表）。失效方向刻意不对称：门未启用/注册表 IO 失败一律 **fail-open**（等同 0.31.x 行为，信任机制绝不把记忆弄死）；注册表文件损坏则 **fail-closed**（回到未信任，重新 `/meow-trust`，代价是一次重复提示而非静默绕过）。
